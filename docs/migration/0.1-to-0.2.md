# Migrating from 0.1.x to 0.2.0

0.2.0 is a **breaking wire-contract release**. Toise realigned onto the **merged**
OpenTelemetry entity-events specification and dropped the transitional
`entity.relation.*` relation extension. Toise is pre-1.0/alpha, so there is **no
compatibility shim** — a 0.1.x producer talking to a 0.2.0 server is silently
ignored (its entities stop being heartbeated and expire). Update the producer and
the server together.

## What is and isn't affected

| Area | Impact |
| --- | --- |
| **OTLP producers** (what an agent emits) | **Breaking** — must adopt the new wire shape below. |
| **Stored event log** (Pebble data dir) | **None** — the internal event model is unchanged; a 0.2.0 server reads a 0.1.x data dir as-is. No data migration. |
| **GraphQL / MCP consumers** | **None** — the query schemas and tools are unchanged. |
| **`toise-server` flags** | **None** — flags keep their names; the new file/env config is additive. |

## The wire changes

### 1. Entity events are identified by `EventName`, not an attribute

| 0.1.x | 0.2.0 |
| --- | --- |
| attribute `otel.entity.event.type` = `entity_state` / `entity_delete` | LogRecord **`EventName`** = `entity.state` / `entity.delete` |

### 2. Attribute keys lose the `otel.` prefix and rename

| 0.1.x attribute | 0.2.0 attribute |
| --- | --- |
| `otel.entity.type` | `entity.type` |
| `otel.entity.id` (map) | `entity.id` (`map<string,string>`) |
| `otel.entity.attributes` (map) | `entity.description` (map) |
| `otel.entity.interval` (int, **milliseconds**) | `entity.report.interval` (int, **seconds**) |

> The interval **unit changed from milliseconds to seconds**. A value of `60000`
> (60 s) becomes `60`. Emitting the old millisecond value would set a ~16-minute
> interval and mis-arm the liveness sweeper.

### 3. Relationships are embedded — the `entity.relation.*` extension is removed

Edges no longer ride on separate relation LogRecords. They are **embedded** on the
source entity's `entity.state` event as an `entity.relationships` array; each
descriptor names the **target** (the source is the emitting entity). Removal is **by
absence** — a relationship the source stops listing is removed; there is no relation
delete on the wire, and **no edge attributes**.

| 0.1.x (extension) | 0.2.0 (embedded) |
| --- | --- |
| `entity.relation.event.type` = `state` / `delete` | (none — lifecycle is the source entity's) |
| `entity.relation.type` | descriptor `relationship.type` |
| `entity.relation.from.{type,id}` | the source entity itself |
| `entity.relation.to.{type,id}` | descriptor `entity.type` + `entity.id` |
| `entity.relation.attributes` | **removed** — model attribute-bearing edges as entities (see [topology as entities](../data-model/otel-mapping.md)) |

## Before / after

A `service.instance` that runs on a host, with a 60-second report interval.

**0.1.x — two LogRecords:**

```
LogRecord A (entity)
  attributes:
    otel.entity.event.type: entity_state
    otel.entity.type:       service.instance
    otel.entity.id:         { service.instance.id: agent-1 }
    otel.entity.attributes: { service.name: senhub-agent }
    otel.entity.interval:   60000          # milliseconds

LogRecord B (relation extension)
  attributes:
    entity.relation.event.type: state
    entity.relation.type:       runs_on
    entity.relation.from.type:  service.instance
    entity.relation.from.id:    { service.instance.id: agent-1 }
    entity.relation.to.type:    host
    entity.relation.to.id:      { host.id: h1 }
```

**0.2.0 — one LogRecord:**

```
LogRecord
  EventName: entity.state
  attributes:
    entity.type:            service.instance
    entity.id:              { service.instance.id: agent-1 }
    entity.description:     { service.name: senhub-agent }
    entity.report.interval: 60             # seconds
    entity.relationships:
      - relationship.type: runs_on
        entity.type:       host
        entity.id:         { host.id: h1 }
```

## Steps for a producer

1. Set the LogRecord **`EventName`** to `entity.state` / `entity.delete` instead of
   the `otel.entity.event.type` attribute.
2. Rename the entity attribute keys and **convert the interval to seconds**.
3. Stop emitting separate `entity.relation.*` records; embed each edge as an
   `entity.relationships` descriptor on its **source** entity's state event, and
   emit the source's *full current* relationship set every time (removal is by
   absence).
4. Move any former edge attributes onto entities (e.g. ports → `network.interface`,
   route `metric` → `network.route`).

The **executable contract** is the conformance fixture
(`internal/ingest/testdata/conformance/entity-events.json`) — emit to reproduce it.
The `cmd/toise-probe` reference producer is a working embedded emitter to copy. The
senhub-agent producer resync is tracked at
[senhub-agent#222](https://github.com/senhub-io/senhub-agent/issues/222).

## Server configuration (new, optional)

0.2.0 adds a YAML config file and `TOISE_*` environment variables (precedence:
defaults < file < env < flags). Existing flag-based invocations are unchanged. See
[Configuring toise-server](../operations/configuration.md).
