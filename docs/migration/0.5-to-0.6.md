# Migrating from 0.5.0 to v0.6.0

v0.6.0 is the **corrective release** for the 0.5.0 audit: every fix in it
makes an existing promise true rather than adding a new one. It is **not** a
wire-contract break and there is **no data migration**. A handful of behaviors
got sharper, and the project's versioning itself changed — read the table.

## What is and isn't affected

| Area | Impact |
| --- | --- |
| **Release tags** | **This release is tagged `v0.6.0`** — v-prefixed, standard Go/semver — and all future server tags follow (`0.1.0`–`0.5.0` are not retro-tagged). Pin scripts and deploy tooling that parse the tag name accordingly: assets and the GHCR image carry the tag verbatim (`toise_v0.6.0_linux_amd64.tar.gz`, `ghcr.io/toise-dev/toise:v0.6.0`); docs URLs keep the unprefixed style (`/docs/0.6.0`). |
| **SDK consumers** | `pkg/emit` is now **its own Go module** released as `pkg/emit/vX.Y.Z` (first: `pkg/emit/v0.1.0`). The import path is unchanged; your module graph shrinks to the OTel pdata types and gRPC. `State`/`Delete` can now return `emit.PartialError` — handle it (see below). |
| **OTLP producers** | **None required.** One failure mode fixed: an unknown `relationship.type` used to wedge the whole export in a retry loop; it is now rejected per record like every other contract violation. |
| **MCP consumers** | **`get_entity` takes `entity_id`** (was `id`) — the one rename, aligning it with every other entity-taking tool. `recent_changes` no longer requires `window` (defaults to 1h). Pre-1970 `as_of`/`from`/`to` values are rejected instead of answering nonsense. |
| **GraphQL consumers** | Pre-1970 `asOf`/`since`/`until`/`asKnownAt` values are rejected. No schema change. |
| **Stored data** (the data dir) | **No migration on upgrade.** Liveness snapshots gain per-producer intervals (additive JSON; 0.5.0 blobs still load — see the boot-grace note). |
| **Operators** | Snapshots are **on by default** (`snapshot_interval: 5m`); `toise-server checkpoint` is **strictly read-only** and refuses dirs it cannot back up; conformance CI may newly fail on a missing `service.instance.id` (advisory). |

## 1. MCP: the `get_entity` rename (the one consumer-visible break)

`get_entity` is called with `entity_id`, like `get_neighbors`,
`entity_history`, `telemetry_keys` and `impact_of`. A client still sending
`id` gets a schema validation error naming the unexpected property. Update the
argument name; nothing else about the tool changed.

## 2. SDK: handle `emit.PartialError`

Toise accepts an export and rejects individual contract-violating records via
OTLP partial success. The SDK used to swallow that signal and return `nil`.
Now:

```go
if err := client.State(ctx, entities...); err != nil {
    var pe emit.PartialError
    if errors.As(err, &pe) {
        // pe.Rejected records were refused (pe.Message = first reason).
        // This is permanent: fix the producer, do not retry as-is.
    }
    // otherwise: transport failure, retry as before
}
```

If you gate CI on the conformance kit: `Check` also returns an *advisory*
problem when a ResourceLogs carrying entity events has no usable
`service.instance.id`. Set a stable instance id (it is what scopes liveness
ref-counting, ADR 0019), or skip `Problem.Advisory` entries explicitly.

## 3. Operators: snapshots on by default, boot grace after downtime

- `snapshot_interval` now defaults to **5m** (was disabled), and a final
  snapshot is written at graceful shutdown. The liveness memento therefore
  works out of the box: producer reference counts survive restarts. To keep
  the old behavior set `snapshot_interval: 0` — the server then warns at boot
  that sweeping is armed without persistence.
- After downtime longer than your producers' heartbeat intervals, restored
  liveness deadlines are floored to `boot + interval`: the server waits one
  full interval before sweeping instead of mass-deleting entities of producers
  that simply have not re-exported yet. A genuinely dead producer is reaped
  one interval later than before — that is the trade-off.
- `toise-server checkpoint` now **refuses** a nonexistent data dir, an
  unmigrated legacy layout (start the server once first), and a dir with no
  tenant stores — previously it minted an empty store and "backed it up"
  silently. It also accepts `--config` so the YAML `data_dir` is honored, and
  never writes to the source. If your backup scripts relied on the old
  tolerant behavior, they were backing up nothing; fix the path, not the
  script.

## 4. Reads during maintenance

`entity_history`, `recent_changes`, `graph_diff`, as-of folds and their
GraphQL equivalents could intermittently fail with `pebble: not found` while
heartbeat coalescing or retention pruning ran. Fixed — no action needed; if
you built retry loops around those errors, you can remove them.

## 5. Upgrade sequence

Nothing special:

1. Stop the server (a final liveness snapshot is written on the way down
   starting only from this version, so this first upgrade still replays
   refs from the log/last snapshot as 0.5.0 did).
2. Optionally `toise-server checkpoint --data-dir <dir> <backup-dir>` with the
   **old** binary if you want a pre-upgrade backup.
3. Install the `v0.6.0` binary, start, verify `toise_build_info` and
   `/healthz`.

Downgrade to 0.5.0 is uneventful for the store itself; new-format liveness
blobs are additive JSON and load fine on 0.5.0.
