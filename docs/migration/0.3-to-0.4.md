# Migrating from 0.3.x to 0.4.0

0.4.0 is the **correctness and LLM-querying** release. It is **not** a
wire-contract break — a 0.3.x OTLP producer keeps working unchanged — and there
is **no data migration**: the on-disk layout and event format are identical.
What changes are a handful of behaviors that were previously broken or too
permissive. An upgrade with no config changes keeps working; read the table to
see which sharper behavior could surprise you.

## What is and isn't affected

| Area | Impact |
| --- | --- |
| **OTLP producers** (what an agent emits) | **Wire contract unchanged.** Two sharper behaviors: a record violating the contract (unknown `entity.type`, malformed identity) is now rejected *per record* via OTLP partial success — its valid siblings land — instead of erroring the whole export; and export failures now carry proper gRPC codes (`InvalidArgument` = do not retry, `Unavailable` = retry) instead of `Unknown`. Spec-compliant exporters behave **better**; an exporter that special-cased `Unknown` should be checked. |
| **MCP consumers** | **Three new tools** (`graph_diff`, `find_path`, `telemetry_keys`) and **changed defaults on the timeline tools** — see below. |
| **GraphQL consumers** | **None.** Schema unchanged. |
| **Stored event log** (the data dir) | **None.** Same layout, same format, no migration. |
| **`toise-server` flags / config** | **Additive**, plus startup **validation** that can reject configs that used to start silently broken — see below. |
| **Multi-tenant deployments** | Unknown tenants are now a **404 on read** (previously reading lazily created a tenant store); creation limits and per-tenant tokens are available, all **opt-in**. |

## 1. MCP timeline tools: heartbeats out, budgets on (the one consumer-visible change)

`recent_changes` and `entity_history` now **exclude `entity.unchanged`
heartbeats by default** and **bound their output** (`limit`, default 50, max
200). On a live instance this is the difference between 5 useful changes and
hundreds of heartbeat records. If you depended on the old firehose:

- pass `include_heartbeats: true` to get heartbeats back;
- raise `limit`, and use the new digest fields (`total`, `truncated`,
  `heartbeats_excluded`, `by_change_type`) to page deliberately.

`count` still means "changes returned". `get_neighbors` results additionally
carry `via_relation` / `direction` / `depth` per neighbor (additive). Every
tool call now runs under a 30-second budget — a call that used to scan
unboundedly now returns a deadline error instead of hanging the session.

## 2. Startup validation can reject a silently-broken config

0.4.0 refuses to start with a configuration that would not do what it says:

- `tls_cert_file` XOR `tls_key_file` (half-set TLS used to silently serve plaintext);
- `retention_max_age` set with no `retention_compaction_interval` (used to silently never prune);
- unknown `log_level` / `log_format` (used to silently fall back).

If your 0.3.x deployment started with one of these, fix the config before
upgrading — the error message says exactly what to change.

## 3. Multi-tenancy: reading no longer creates, and you can bound creation

- A query (GraphQL/MCP/debug UI) for a tenant that does not exist returns
  **404** instead of creating an empty store on disk. Ingest still creates
  tenants on first write (unless you bound it).
- New, all opt-in: `tenant_auto_create: false` (only pre-existing tenants are
  served), `tenant_allowlist` (only these ids may be created), `max_tenants`
  (cap). Persisted tenants and `default` always open.
- New: `TOISE_TENANT_TOKENS` takes `tenant:token` pairs to bind a token to one
  tenant (HTTP 403 / gRPC `PermissionDenied` elsewhere). Tokens from
  `TOISE_AUTH_TOKENS` stay global. With no tokens at all, the trusted-network
  posture is unchanged.

## 4. Operational changes you will notice (and want)

- Deploys exit **0** even with connected MCP/WebSocket clients (used to burn
  the 5s shutdown grace and exit `1/FAILURE`).
- `/metrics` gains ingest counters (`toise_ingest_exports_total`,
  `toise_ingest_records_total{result}`, tenant rejections, auth failures) —
  alert on `outcome="error"` and on a flat `handled` rate.
- `toise_entities_by_type` reports the top 50 types plus an `other` bucket.
- `toise-server checkpoint [--data-dir d] <dst>` is the supported cold-backup
  command (run it with the server stopped).
- Maintenance (heartbeat coalescing, retention pruning) no longer pauses
  ingestion while it scans.

## 5. Recommended upgrade sequence

1. Back up: stop the server, `toise-server checkpoint --data-dir <data> <backup-dir>`
   (or copy the data dir), restart the old binary if you need time.
2. Check the config against §2 (TLS pair, retention/compaction, log level).
3. Swap the binary and start. Watch `/readyz`, `toise_build_info`, and the new
   `toise_ingest_exports_total{outcome="ok"}` for movement.
4. If you run multi-tenant exposed: set `TOISE_TENANT_TOKENS` and creation
   bounds (§3) — this is the release that makes that posture safe.
