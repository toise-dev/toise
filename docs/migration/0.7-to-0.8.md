# Migrating from v0.7.0 to v0.8.0

v0.8.0 is the **SaaS-readiness release**: it *adds* access security, resilience/HA,
a multi-source identity overlay, and an attribute-enrichment pass. It is **not** a
wire-contract break and there is **no data migration**. Everything new is **opt-in**
— upgrade in place, change nothing, and the server behaves exactly as it did on
0.7.0. Reach for the new features only when you need them.

## What is and isn't affected

| Area | Impact |
| --- | --- |
| **Operators / auth** | **None required.** Auth, OIDC, mTLS, RBAC, audit log, derive-only tenancy, backups, log shipping, tenant caps — all **off by default**. `TOISE_AUTH_TOKENS` still means full access on both surfaces. Adopt what your tier needs (see the [Deployment tiers & SaaS guide](../user-guide/docs/operations/saas.md)). |
| **MCP consumers** | **None required.** `get_entity` may now include a `canonical` block (entities a high-confidence `same_as` asserts are the same thing — a read-time view, additive); `impact_of` may report an `aliases` count and fold a machine's facets together; `describe_schema` advertises a governance-attribute vocabulary. Existing calls are unchanged. |
| **GraphQL consumers** | **None required.** The `entities` query gains an optional `match` filter (parity with `find_entities`). No change to existing queries or types. |
| **OTLP producers** | **None required.** New optional vocabulary is *accepted*, not demanded: the `same_as` relation, the governance attribute keys, and the AT8–AT13 descriptive keys. One consistency note: the network-interface state key is `oper_state` (underscore) — the engine's recognized spelling; emit that, not `oper.state`, for a link up/down to classify as a state change. |
| **Stored data** (the data dir) | **No migration on upgrade.** Hashed tokens, the audit log, and shipped segments are all new, separate artifacts created only when configured. A downgrade ignores them. |
| **Release tags** | `v0.8.0` (server). The `pkg/emit` SDK module is **unchanged** since 0.7.0 (still `pkg/emit/v0.2.0`) — no SDK upgrade needed. Assets and the GHCR image carry the tag verbatim (`toise_v0.8.0_linux_amd64.tar.gz`, `ghcr.io/toise-dev/toise:v0.8.0`); docs URLs keep the unprefixed style (`/docs/0.8.0`). |

## Adopting the new features (optional)

- **Harden a node:** `--production` (dev surfaces off), TLS, `auth_tokens`, scheduled
  backups (`backup_dir` + `backup_interval`).
- **Go multi-tenant SaaS:** `tenant_trust_mode: derive-only`, per-tenant scoped
  tokens, OIDC (`oidc_*`), mTLS ingest (`tls_client_ca_file`), the audit log
  (`audit_log`).
- **Durability & HA:** log shipping (`log_shipping_dir` or `log_shipping_s3_*`),
  read replicas, tenant sharding (`max_tenants` + a disjoint `tenant_allowlist`).

Each is independent. The [Deployment tiers & SaaS operations](../user-guide/docs/operations/saas.md)
guide walks the full progression; the [configuration reference](../user-guide/docs/configuration.md)
lists every key.

## The one thing to check: `oper_state`

If you operate a producer that emits `network.interface` state, make sure it sends
the key `oper_state` (underscore), not `oper.state`. Only `oper_state` is in the
engine's recognized state-key set, so an interface up/down flip emitted as
`oper.state` classifies as a plain attribute update rather than a state change.
This was always the engine's behavior; 0.8.0 fixes the contract docs and the
reference producer to match it.
