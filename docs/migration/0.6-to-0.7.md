# Migrating from v0.6.0 to v0.7.0

v0.7.0 is the **integration release**: it mostly *adds* surface (annotations,
MCP resources/prompts, token roles, verbosity, a conformance CLI). It is **not**
a wire-contract break and there is **no data migration**. One MCP argument was
renamed — that is the only consumer-visible break.

## What is and isn't affected

| Area | Impact |
| --- | --- |
| **MCP consumers** | **`get_neighbors` takes `max_depth`** (was `depth`), matching `find_path` and `impact_of`. One rename — update the argument name. Everything else is additive: a new `verbosity` arg (optional), a new `annotate_entity` tool, plus resources and prompts your client may now list. |
| **GraphQL consumers** | Additive: a new `annotations` field on `Entity` and the first mutation, `annotateEntity`. No change to existing queries or types. |
| **OTLP producers** | **None required.** New `compute.vm` and `container` types are accepted by the built-in registry. The SDK now rejects a malformed `eventName` or a sub-second `Interval` locally (a programming error, not a wire change). |
| **Operators / auth** | **None required.** Token roles are additive: `TOISE_AUTH_TOKENS` stays full (both surfaces). Optionally add `TOISE_READ_TOKENS` (query-only) or `TOISE_INGEST_TOKENS` (OTLP-only) for least privilege. |
| **Stored data** (the data dir) | **No migration on upgrade.** Operator annotations live in a **new per-tenant sidecar** (`<data-dir>/<tenant>/annotations`), created on first use — separate from the event log, never replayed. A downgrade simply ignores it. |
| **Release tags** | `v0.7.0` (server) and `pkg/emit/v0.2.0` (SDK module) follow the v-prefixed scheme from v0.6.0. Assets and the GHCR image carry the tag verbatim (`toise_v0.7.0_linux_amd64.tar.gz`, `ghcr.io/toise-dev/toise:v0.7.0`); docs URLs keep the unprefixed style (`/docs/0.7.0`). |

## 1. MCP: the `get_neighbors` rename (the one consumer-visible break)

`get_neighbors` is now called with `max_depth`, like `find_path` and
`impact_of`. A client still sending `depth` gets a schema validation error
naming the unexpected property. Update the argument name; nothing else about the
tool changed (the default is still one hop, capped at 5).

## 2. Annotations are an overlay, not producer truth

`annotate_entity` / the `annotateEntity` mutation write operator notes into a
per-tenant sidecar. They surface on `get_entity` and `Entity.annotations` but
**never** become identifying or descriptive attributes, never enter the event
log, and are never replayed or time-travelled. They are the one write either
read surface exposes, so they require a **write-capable** token (full or
tenant-scoped); a read-only token is refused. With auth disabled (a trusted
network) any caller may annotate.

## 3. Token roles (optional)

If you split read and write clients, give each the narrowest token:

- `TOISE_AUTH_TOKENS` — full: both the query surfaces and OTLP ingest.
- `TOISE_READ_TOKENS` — the query surfaces only (GraphQL, MCP, debug UI); refused
  on `annotate_entity` and on ingest.
- `TOISE_INGEST_TOKENS` — OTLP ingest only; refused on the query surfaces.

All three are env-only secrets, comma-separated, same as before. Existing
single-token setups keep working unchanged.

## 4. Validate producers with the conformance CLI

`toise-conformance` checks a producer's OTLP output against the contract without
a running Toise — useful in producer CI, in any language:

```bash
go install github.com/toise-dev/toise/pkg/emit/cmd/toise-conformance@latest
my-producer --dump-otlp | toise-conformance      # exit 0 = conformant
```

See the [Producer directory](https://toise.dev/docs/latest/producers/) for the
full catalog.
