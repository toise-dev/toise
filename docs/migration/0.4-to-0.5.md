# Migrating from 0.4.x to 0.5.0

0.5.0 is the **time-travel and producer-SDK** release. It is **not** a
wire-contract break — a 0.4.x producer keeps working unchanged, and the new
`pkg/emit` SDK is purely additive — and there is **no data migration**. A few
behaviors got sharper; read the table.

## What is and isn't affected

| Area | Impact |
| --- | --- |
| **OTLP producers** | **None required.** Additive option: build on `pkg/emit` (and run `pkg/emit/conformance` in your CI) instead of hand-rolling the wire contract. With `accept_unknown_types: true` (opt-in, off by default) Toise also accepts well-shaped types outside its built-in registry. |
| **MCP consumers** | **Two new tools** (`impact_of`, `describe_type` — eleven total) and `as_of` on every graph-reading tool. Additive. `get_entity` on an old deletion may now answer not-found (see tombstones below). |
| **GraphQL consumers** | `asOf` on `entity`/`entities`/`relations`; subscriptions take a `ChangeFilter` and events carry a `dropped` field (additive). **`first` is now clamped to 200** — a consumer passing more gets 200 per page (pageInfo still paginates). |
| **Stored data** (the data dir) | **No migration on upgrade.** The store stamps a format-version marker and snapshots gain a liveness section — see the downgrade note. |
| **`toise-server` flags / config** | **Additive** (`accept_unknown_types`). |
| **TLS deployments** | **Floor raised to TLS 1.2** and the certificate is re-read per handshake — renewals apply without a restart. Clients stuck below 1.2 (none should exist) would fail to connect. |

## 1. Tombstone retention (the one consumer-visible change)

Soft-deleted entities used to stay readable by id forever. Now the most recent
**1024 deletions per tenant** stay readable (`deleted: true`); older tombstones
read as **not-found**, and the error points at `entity_history`, where the full
past always lives in the log. If you depended on reading very old deletions by
id, switch to `entity_history` (or `as_of` at a time the entity was alive).

## 2. Downgrade note (pre-1.0, but worth knowing)

A snapshot written by 0.5.0 carries a liveness section a 0.4.x binary cannot
parse: a **downgrade** after a 0.5.0 snapshot fails at boot with "snapshot
truncated". Recovery: delete the snapshot (it is a restart accelerator, not
data — the log replays in full) or restore the pre-upgrade backup. Upgrades
are unaffected: 0.4.x snapshots read fine.

## 3. New operational signals worth wiring

- `toise_maintenance_runs_total{op,outcome,tenant}` and
  `toise_maintenance_last_duration_seconds{op,tenant}` — alert on
  `outcome="error"` per tenant.
- `toise_ingest_unknown_type_records_total` — non-zero means a producer emits
  types outside the registry (only with `accept_unknown_types`).
- Subscriptions: a `dropped > 0` on a received event means your consumer fell
  behind — re-query state, then resume.

## 4. Recommended upgrade sequence

1. Back up: `toise-server checkpoint --data-dir <data> <backup-dir>` (server
   stopped).
2. Swap the binary and start; watch `/readyz` and `toise_build_info`.
3. If you run subscriptions, adopt the `dropped` field; if you page GraphQL
   with `first > 200`, adapt to the clamp.
4. Producers: consider switching emission to `pkg/emit` and adding
   `conformance.Check` to your CI — output that passes is never rejected
   per-record for shape reasons. A registered `entity.type` is still required
   under the default strict vocabulary; `accept_unknown_types` lifts that.
