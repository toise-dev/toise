# Gap analysis — spec 1.58.0 `entity-events.md` vs Toise ingestion contract

Date: 2026-06-22
Author lane: SIG liaison (research). Verified against Toise Go code + spec source.

> **Correction (2026-06-22, post-review):** an earlier version of this digest
> claimed the relationship descriptor key diverged (`type` upstream vs
> `relationship.type` in Toise). That was a misread of the spec. The 1.58.0
> normative file uses **`relationship.type`** (verified verbatim at tag
> `v1.58.0`), which is exactly what Toise reads (`pkg/emit/wire/wire.go`
> `RelType = "relationship.type"`, consumed by `internal/ingest/embedded.go`).
> **There is no divergence.** Verdict below updated accordingly.

## Headline verdict

**Fully aligned — no ingestion change required.** The normative form that landed
in spec release 1.58.0 matches Toise's ingestion contract on every load-bearing
point: identification by `EventName` (`entity.state` / `entity.delete`),
attributes in `LogRecord.Attributes` with the bare `entity.` prefix,
delete-by-explicit-event-plus-Interval-backstop, embedded relationships on the
state event, and the relationship descriptor keys (`relationship.type`,
`entity.type`, `entity.id`). The only open items are a few **new optional fields**
in 1.58.0 that Toise can adopt later for richness — none of them a break.

## What landed in 1.58.0

- Changelog line: "Add specification for communicating entity information as
  structured log events." Behind it: **spec PR #4836** (dmitryax), merged
  2026-06-04, shipped in the 2026-06-22 release.
- The wire contract now lives in a dedicated normative file:
  `specification/entities/entity-events.md`. **Status: Development** — normative
  MUST/SHOULD language, not yet stable.
- Source read: raw file at tag `v1.58.0`.

### Normative form (1.58.0), verbatim where it matters

- **Identification:** the **`EventName` field of the LogRecord** = `entity.state`
  or `entity.delete`. No `event.name` attribute.
- **State event required attrs:** `entity.type` (string), `entity.id`
  (map<string,string>, >= 1 entry, string keys+values).
- **State event optional attrs:** `entity.description` (map<string,AnyValue>);
  `entity.relationships` (array of maps); `entity.report.interval` (int64 s,
  `0` == no periodic events).
- **Relationship descriptor (each map):** `relationship.type` (string),
  `entity.type` (string, target type), `entity.id` (map<string,string>, target
  identity). **Verified verbatim — the key is `relationship.type`, not bare `type`.**
- **Delete event:** required `entity.type` + `entity.id`; optional
  `entity.delete.reason` (string; e.g. "terminated", "expired", "evicted",
  "user_requested", "scaled_down"). Delete delivery not guaranteed; fall back to
  expiry via `entity.report.interval`.
- All keys use the **bare `entity.` prefix**, not `otel.entity.`.

## Toise ingestion contract (verified against Go code on `main`)

- Keys each LogRecord by **`EventName`**; `entity.state` (upsert) /
  `entity.delete` (soft delete); other records ignored.
- Required: `entity.type`, `entity.id` (map<string,string>).
- Relationships: embedded `entity.relationships` array on `entity.state`; each
  descriptor read as `{ relationship.type, entity.type, entity.id }`
  (`internal/ingest/embedded.go` via `relDescType = wire.RelType =
  "relationship.type"`); removed-by-absence on next state event.
- Delete: explicit `entity.delete` + `entity.report.interval` sweeper backstop.

## New in 1.58.0 that Toise does not yet handle (all optional, no urgency)

- `entity.delete.reason` (item 7) — additive optional string; ingesting it would
  let the change-taxonomy/LLM surface *why* something was deleted. Low effort,
  good consumer-side value. Future-proofing.
- `entity.report.interval == 0` semantics (item 5) — spec assigns `0` the meaning
  "no periodic state events." Confirm Toise's sweeper treats `0` as "do not expire
  on cadence" rather than immediate/unknown. Minor correctness check.
- `entity.description` AnyValue (item 4) — spec permits arrays/nested maps;
  Toise flattens/drops with a Warn (a documented faithful-store choice, not a break).

## Concrete Toise actions (proposed, for maintainer decision)

1. **No near-term ingestion change.** The relationship-key concern was a false
   alarm — spec and code both use `relationship.type`.
2. **Low-priority future-proofing** (batch later, user's code lane): handle
   `entity.delete.reason`; confirm `entity.report.interval == 0` = no cadence
   expiry; document that `entity.description` may carry nested AnyValue per spec.
3. **Liaison note:** no upstream engagement required for alignment. The merged
   wire contract validates Toise's ingestion design almost exactly — a credibility
   point for our later temporal/lifecycle contribution (the spec still has no
   change-type; our taxonomy + bi-temporality remain the unfilled gap).
