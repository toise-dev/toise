# Security Policy

## Supported versions

Toise is released as tagged versions (`vX.Y.Z`); pre-releases (`-beta.N`) are
test artefacts and are never supported. Security fixes land on the `main` branch
and are delivered in the next release from it. Only the **most recent release**
receives them: there is no back-porting to earlier minor versions today, so
running an older one means running without the fixes.

The length of time a given release stays supported is not yet stated here. Until
it is, do not infer one.

## Reporting a vulnerability

We take security issues seriously and appreciate responsible disclosure.

**Do not report security vulnerabilities through public GitHub issues,
discussions, or pull requests.**

Instead, please report them by email to **security@sensorfactory.fr**, the
single point of contact for vulnerability reports about Toise.

If you prefer to report through GitHub, open a security advisory via the
repository's **Security → Advisories** tab, which keeps the report private to
the maintainers. Either route reaches us; neither is a fallback for the other.

When reporting, please include as much of the following as you can:

- A description of the vulnerability and its impact.
- Steps to reproduce, or a proof of concept.
- The affected component, commit, or version.
- Any suggested remediation, if you have one.

## What to expect

- We will acknowledge receipt of your report within **5 business days**.
- We will work with you to understand and validate the issue.
- We will keep you informed of progress toward a fix.
- We will credit you in the disclosure unless you prefer to remain anonymous.

We ask that you give us a reasonable amount of time to address the issue before
any public disclosure, and that you avoid privacy violations, data destruction,
and service interruption while researching.

Thank you for helping keep Toise and its users safe.
